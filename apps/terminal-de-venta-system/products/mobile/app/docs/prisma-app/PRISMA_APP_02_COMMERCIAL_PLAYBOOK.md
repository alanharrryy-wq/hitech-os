# PRISMA App - Commercial playbook

## Authority note

This document is commercial messaging only. It does **not** define Mobile information architecture. Product-interface authority lives exclusively in:

`PRISMA_MOBILE_INTERFACE_CANON.md`

## Posicionamiento

PRISMA App es la capa móvil de visibilidad y mando para dueños y supervisores.

No se vende como "app multisucursal". Se vende como:

```text
Tu negocio al día, desde tu celular.
```

## Mensaje base

Consulta el pulso del negocio, ventas, caja, inventario y las decisiones que requieren atención desde el celular sin estar físicamente en el local.

## Rol dentro de PRISMA

```text
Tablet opera y vende de forma independiente.
PC administra y gobierna cuando existe.
PRISMA Mobile supervisa, resume, prioriza y orienta decisiones.
```

## Dolor del cliente

El dueño normalmente depende de llamadas, WhatsApps, cortes manuales, fotos de tickets, capturas de pantalla, reportes tarde o del clásico "todo bien" sin evidencia. PRISMA Mobile convierte ese ruido en una lectura rápida, trazable y accionable.

## Pitches por tipo de cliente

### Cliente de una tienda

```text
Con PRISMA Mobile puedes ver cómo va tu negocio hoy: venta, caja, productos que requieren atención y decisiones importantes desde el celular.
```

### Cliente con empleados

```text
PRISMA Mobile te ayuda a supervisar caja, ventas, inventario y señales operativas sin estar encima del mostrador todo el día.
```

### Cliente multisucursal

```text
Si tienes varias tiendas, cambias de contexto desde el mismo Mobile y ves cuál necesita atención sin convertir MultiSucursal en otra app.
```

## Qué no decir

- app solo para cadenas;
- app solo para multisucursal;
- vigilancia de empleados;
- reemplazo de PC;
- reemplazo de Tablet;
- Mobile como requisito para vender;
- Mobile como autoridad para inventar o corregir datos operativos.

## Qué sí decir

- visibilidad móvil;
- pulso del negocio;
- decisiones priorizadas;
- caja e inventario en contexto;
- mando del dueño;
- contexto multisucursal cuando aplica;
- datos con fuente, frescura y confianza visibles.

## Jerarquía comercial de producto

Para explicar la app a un cliente, la referencia canónica es:

```text
Inicio / Pulso
Ventas
Caja
Inventario
Mando
Sistema
```

Mando reúne Command Center, Action Inbox, Daily Brief, Decision Ledger, Pulse Timeline y Health Radar. MultiSucursal es contexto global. Alertas alimentan Mando. Reportes ejecutivos viven en Daily Brief y resúmenes contextuales. Sync, licencias, dispositivos, setup y diagnóstico viven en Sistema.

## Objeciones

### "Yo solo tengo una tienda"

```text
Perfecto. Mobile empieza por el pulso de tu negocio, ventas, caja, inventario y mando. El cambio de sucursal solo aparece cuando realmente lo necesitas.
```

### "No quiero revisar otro sistema"

```text
No es otro backoffice. Es una lectura rápida para saber qué está bien, qué cambió y qué necesita atención.
```

### "¿Me va a llenar de alertas?"

```text
La meta no es llenarte de notificaciones. Mando prioriza señales y acciones para que veas primero lo que realmente importa.
```

## Regla comercial de verdad

No prometer una interfaz, dato, acción, mutación o capacidad que no tenga evidencia técnica suficiente. El producto puede tener un canon aspiracional, pero una demo o promesa comercial debe distinguir con claridad entre objetivo de producto y capacidad implementada/certificada.

## Internal testing

The Play Store release path must mention internal testing before production promotion.
