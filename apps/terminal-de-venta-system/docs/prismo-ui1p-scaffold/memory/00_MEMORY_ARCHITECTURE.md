# Memory Architecture · PRISMO UI1P PRO

PRISMO no sólo responde. Debe recordar **qué sabe**, **qué pasó**, **qué procedimiento funcionó**, **qué está pasando ahora**, y **qué regla visual/operativa gobierna la respuesta**.

## 1. Semantic Memory
Hechos estables:
- nombres de módulos;
- diccionario técnico → humano;
- arquitectura;
- rutas;
- contratos;
- términos de negocio;
- canon visual.

## 2. Episodic Memory
Eventos fechados:
- learn1 PASS;
- learn2 fail/fix/pass;
- learn3 fail/fix/pass;
- learn4 fail/fix/pass;
- evidence_count 688;
- pattern_count 18;
- protocol_count 13;
- learn5 reservado/no ejecutado.

## 3. Procedural Memory
Recetas que se pueden repetir:
- cómo ejecutar zip;
- cómo hacer rollback;
- cómo validar PASS real;
- cómo leer result/fail zip;
- cómo corregir protocol_stats legacy list;
- cómo evitar fake green;
- cómo construir UI package con PowerShell wrapper + Python engine.

## 4. Working Memory
Estado de la conversación/pregunta:
- objetivo elegido;
- dominio elegido;
- lente elegido;
- escena elegida;
- texto libre;
- contexto breve;
- filtros y reformulaciones.

## 5. Operational Memory
Estado runtime y artefactos:
- endpoints learning;
- reports;
- store size;
- vault records;
- latest result zip;
- warnings activos;
- alignment needs_review.

## 6. Governance Memory
Reglas:
- no DB;
- no `.env`;
- no deploy;
- no raw HTML;
- no etiquetas de incompleto;
- internal safety only;
- no raw evidence flood;
- no G5 en tablas densas.

## 7. Visual Memory
Decisiones visuales:
- Cloudglass Executive OS;
- refrigerant green crystal;
- graphite depth;
- G1-G4 material levels;
- R1-R3 rims;
- N1-N3 semantic glow;
- motion profiles;
- reduced motion frame bonito.

## Ruta de uso
El composer produce `working_memory`. El backend/bridge cruza working memory con semantic/episodic/procedural/operational/governance/visual memory y devuelve un render plan.
