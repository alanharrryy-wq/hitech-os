
# PRISMA Visual System Master

The PRISMA Visual System is a governed platform for all PRISMA surfaces. It is not a CSS cleanup. It is a growth model for building screens using canonical visual primitives, surface adapters, runtime background contracts, machine-readable registries, validation gates, and evidence.

## System flow
`shell -> background runtime -> layer model -> layout -> component family -> surface adapter -> tokens/recipe -> QA -> manifest -> rollback`

## Core principles
- Clarity outside, complexity inside.
- Shared language, surface-specific behavior.
- Runtime backgrounds are governed assets, not local CSS decoration.
- Components carry status: `live`, `mapped`, `planned`, `reserved`, `deprecated`.
- Future support is reserved now, but never falsely marked live.
- Visual QA must distinguish structural PASS from rendered PASS.

## Required base implementation
Codex must implement a living base, not a document shrine. The base must include schemas, registries, templates, validators, reports, and continuation.
