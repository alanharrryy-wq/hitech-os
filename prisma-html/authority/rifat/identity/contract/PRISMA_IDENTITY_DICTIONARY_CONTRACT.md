# PRISMA Identity Dictionary Contract

## Purpose

PRISMA visual identity is a governed neutral meaning system. Screens, routes and CSS files are projections of that meaning, never the authority itself.

## Mandatory order

1. Semantic token meaning.
2. Identity profile or recipe.
3. Surface adapter.
4. Certified owner, route, region, layer and editable-slot binding.
5. Deterministic compiled projection.
6. Runtime projection under a separate task-scoped authority gate.
7. Static and visual evidence with rollback.

## Hard rules

- No runtime claim without certified surface bindings.
- No visual green from functional smoke alone.
- No global CSS blast or priority override declaration.
- No dark Tablet identity unless explicitly re-authorized.
- Use the fewest containers possible. Nested panels require an optical or semantic justification.
- A visual knob at zero must produce real transparency for its governed layer.
- Identity changes must preserve functional behavior, tenant scope, data provenance, accessibility and user state.
- Generated runtime is never edited manually.
- Every activation and projection requires reversible evidence.

## Iteration 1 boundary

This iteration selects and compiles identity authority only. It produces no runtime mutation, no DB/Prisma work, no sync work, no backend change, no deploy, no process operation and no port operation.
