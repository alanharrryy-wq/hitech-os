
# Universal Execution Framework

This bundle is a **governed operating system for AI-assisted software execution across multiple chats**.

It is designed for the default pattern:

- **1 governance chat**
- **6 parallel package chats**

The governance chat acts as the constitutional layer and, by default, also acts as mission control for rounds, bundle validation, and integration decisions.

## What this bundle contains

### 1. Constitutional core
`00-governance-core/` holds the rules that outrank every tactical mechanism:
- operating model
- idea intake and homologation
- run lifecycle and run ID standard
- canonical source rules
- documentation layering
- change budgets
- package boundaries and merge rules
- review, escalation, and decision logging

### 2. Default six-package topology
The six package folders provide a universal default package model that works for websites, portals, APIs, SaaS products, migrations, refactors, and debugging campaigns without baking in one company or one cloud provider.

### 3. Tactical parallel execution subsystem
`docs/parallel_execution/`, `configs/execution_framework/`, `prompts/execution_framework/`, `schemas/execution_framework/`, `tools/execution_framework/`, and `tests/execution_framework/` provide the reusable mechanics for:
- rounds
- work packets
- worker bundles
- validation
- overlap detection
- acceptance reports
- retry prompts
- integration readiness summaries

### 4. Templates and examples
`templates/execution_framework/` contains reusable project, package, and run templates.
`examples/execution_framework/` contains optional reference material when present.

### 5. Nested starter zip
`universal_execution_starter_kit_v1.zip` is the reusable inner starter kit. It contains only the reusable foundation and does not depend on the outer bundle.

## Operator hardening additions
This additive patch introduces the missing operational middle:
- `OPERATOR_ONE_PAGE_FLOW.md` for the fastest safe path under time pressure
- `ops/projects/` as the home of homologated project baselines
- readiness gates and a readiness checker
- explicit inter-chat communication policy
- explicit waiver and exception policy
- contract versioning rules and a contract register template
- canonical tree hygiene rules for clean starter assets and clean tree docs
- a controlled pilot playbook for real `run-001` execution

## Source precedence used to build this bundle
- The **constitutional backbone** comes from the governing package philosophy in Zip A.
- The **tactical execution mechanics** come selectively from Zip B.
- When the two conflicted, the constitutional layer won by default unless an explicit override was justified in the diagnostic material.

## How to use this tomorrow morning
1. Read `OPERATOR_ONE_PAGE_FLOW.md`.
2. Read `STARTER_INDEX.md`.
3. Run the install smoke checks.
4. Bootstrap the project baseline under `ops/projects/<project_id>/`.
5. Freeze the active package topology and runtime path policies.
6. Open Chat 0 for governance.
7. Open Chats 1 through 6 for the six packages.
8. Initialize the run and first round.
9. Generate work packets and prompts.
10. Execute, validate, accept or reject, integrate, and iterate.

## Authority rule
If a prompt, packet, or example contradicts the frozen governance docs, the prompt, packet, or example is wrong.
