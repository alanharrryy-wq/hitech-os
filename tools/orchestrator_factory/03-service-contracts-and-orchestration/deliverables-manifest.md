    # Deliverables Manifest for 03-service-contracts-and-orchestration

    ## Target document set
    - service inventory
- API, event, or task contract map
- request and response contracts
- error and retry contract
- orchestration flow map
- integration boundary rules
- service wiring decisions
- payload examples and mock contracts

    ## Minimum quality bar
    - each deliverable has owner and consumers
    - each deliverable includes non-goals
    - each deliverable has acceptance criteria
    - each deliverable uses canonical terms
    - each deliverable stays inside package responsibility
    - each deliverable can be traced back to the active project baseline

    ## Packaging rule
    Do not merge half-defined deliverables into another package. Freeze locally, then hand off through the merge protocol.
