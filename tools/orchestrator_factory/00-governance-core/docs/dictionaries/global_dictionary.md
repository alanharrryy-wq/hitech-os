# Global Dictionary

## Purpose
Create one canonical language so multiple chats do not invent competing dialects.

## Core terms

### Project
The durable initiative being executed, tracked by `project_id`.

### Homologation
The act of converting a vague idea into a governed project baseline.

### Package
A bounded responsibility slice that owns specific documents and later may own specific runtime paths.

### Run
A bounded execution campaign inside one project, tracked by `run_id`.

### Round
A synchronization window inside a run, tracked by `round_id`.

### Work packet
The active tactical packet that tells one package chat what it may touch in one round.

### Bundle
The submission artifact produced for validation and possible integration.

### Canonical source
The authoritative artifact for a fact, rule, or interface.

### Freeze
The state where an artifact is safe for downstream reliance.

### Handoff packet
The metadata packet that tells downstream consumers what was produced, at what freeze level, and with what open issues.

### Decision record
The artifact that captures a consequential choice, its reasoning, and its downstream effects.

### Runtime path
A project path outside the framework docs, assigned to a package during homologation or a recorded override.

### Evidence
The artifacts proving that work happened, passed review, and is safe to integrate.

## Vocabulary rules
- formal docs use canonical terms
- project-specific glossary extensions require governance approval
- examples may use domain words, but those words do not become canonical automatically
